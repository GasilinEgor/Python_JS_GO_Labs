## 1. Режимы работы

### 1.1 Режим Single
Режим Single это однопоточный режим заполнения базы данных.

Алгоритм работы режима:

1. Создаётся пул UUID.
2. Открывается соединение с PostgreSQL.
3. Формируется очередной пакет данных.
4. Выполняется SQL-запрос на вставку.
5. Обновляются счётчики обработанных и вставленных строк.
6. Процесс повторяется до обработки заданного количества строк

#### 1.1.1 Команды запуска

Шаблон команды запуска:

python main.py  --mode single --db-url [Ссылка на БД] --rows [Количество строк] --unique-file-ids [Размер пула UUID] --batch-size [Размер батча]

ИЛИ:

python main.py  --mode single --db-host [Хост БД] --db-port [Порт БД] --db-user [Имя пользователя БД] --db-password [Пароль пользователя БД] --db-name [Название БД] --rows [Количество строк] --unique-file-ids [Размер пула UUID] --batch-size [Размер батча]

Пример команды запуска режима:

python main.py --mode single --db-url postgresql://postgres:postgres@localhost:5433/pract3 --rows 100000 --unique-file-ids 1000 --batch-size 500

### 1.2 Режим Threading
Режим Threading это многопоточный режим заполнения базы данных.

В многопоточном режиме работа распределяется между несколькими потоками: общее количество строк делится на число работников и каждый поток получает свою долю записей и самостоятельно выполняет пакетную вставку.

Для каждого потока используется отдельное соединение с базой данных, получаемое через SQLAlchemy Engine. Пока один поток ожидает ответа PostgreSQL, другой может продолжать выполнение.

При этом выполнение CPU-bound операций на Python-коде ограничивается GIL, поэтому увеличение количества потоков не обязательно приводит к пропорциональному ускорению.

#### 1.2.1 Команды запуска

Шаблон команды запуска:

python main.py  --mode threading --workers [количество потоков] --db-url [Ссылка на БД] --rows [Количество строк] --unique-file-ids [Размер пула UUID] --batch-size [Размер батча]

ИЛИ:

python main.py  --mode threading --workers [количество потоков] --db-host [Хост БД] --db-port [Порт БД] --db-user [Имя пользователя БД] --db-password [Пароль пользователя БД] --db-name [Название БД] --rows [Количество строк] --unique-file-ids [Размер пула UUID] --batch-size [Размер батча]

Пример команды запуска режима:

python main.py --mode threading --workers 8 --db-url postgresql://postgres:postgres@localhost:5433/pract3 --rows 100000 --unique-file-ids 1000 --batch-size 500

### 1.3 Режим Multiprocessing
Режим Multiprocessing это многопроцессный режим заполнения базы данных.

В  нём создаются несколько независимых отдельных потоков со своим виртуальным окружением и ячейками памяти. Это позволяет выполнять CPU-bound (операции на процессоре) параллельно, что повышает скорость работы программы.

В нашем случае каждый процесс также имеет собственное подключение к БД, что улучшает скорость взаимодействия с ней.

#### 1.3.1 Команды запуска

Шаблон команды запуска:

### 1.4 Режим Asyncio
Режим Ayncio это асинхронный режим заполнения базы данных.

В отличие от потоков и процессов, асинхронные задачи выполняются в рамках одного потока и переключаются между собой в моменты ожидания операций ввода-вывода. Для асинхронного взаимодействия к БД используется асинхронный движок.

Алгоритм работы:
1. Создаётся асинхронный SQLAlchemy Engine.
2. Общее количество строк распределяется между работниками.
3. Для каждого работника создаётся асинхронная задача через asyncio.create_task().
4. Задачи формируют пакеты данных и выполняют асинхронные SQL-запросы.
5. asyncio.gather() ожидает завершения всех задач и собирает результаты.
6. После завершения работы закрывается асинхронный Engine через await engine.dispose().

#### 1.4.1 Команды запуска

Шаблон команды запуска:

python main.py  --mode asyncio --workers [количество потоков] --db-url [Ссылка на БД] --rows [Количество строк] --unique-file-ids [Размер пула UUID] --batch-size [Размер батча]

ИЛИ:

Пример команды запуска режима:

# 2.2 Выводы по таблице

Относительно однопоточного режима каждый из следующих отработал быстрее. Однако, преимущество в скорости было компенсировано в затратах памяти, лучше всего это видно у многопоточного и асинхронного режимов. При этом отношения между их улучшением скорости и увеличением памяти одинаковое, поэтому, вероятно, при увеличении количества потоков, режим Threading может сравняться с режимом multiprocessing.

Режим Asyncio же показал незначительное увеличение памяти, при улучшении времени. При этом изменение времени в 2 раза больше, чем изменение памяти. Данный режим демонстрирует более сбалансированные изменения значений.

В результате, если необходимо выполнить задачу максимально быстро, то подходит мултипроцессный режим. Если же есть ограничение по затрачиваемой памяти, лучше подойдёт асинхронный режим. В случае необходимости прироста скорости и более чуткого контроля памяти, можно выбрать многопоточный режим и грамотно находить максимально возможное количество потоков.
